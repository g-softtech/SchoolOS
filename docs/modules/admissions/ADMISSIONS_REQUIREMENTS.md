# Admissions Module: Functional Requirements

## Overview
The Admissions Module is the reference implementation for all business vertical slices in SchoolOS. It governs the end-to-end process of prospective students applying to a school, being evaluated, and being formally admitted and transitioned into the Student module.

## Enterprise Core Capabilities
1. **Admission Workflow Engine:** Status transitions are NOT hardcoded. Each school can configure its own custom pipeline (e.g., Application -> Entrance Exam -> Interview -> Medical -> Acceptance).
2. **Admission Form Builder:** Schools can build custom application forms (`AdmissionField`, `AdmissionFieldOption`) without code changes (e.g., Religion, Blood Group, Previous School).
3. **Dynamic Document Rules:** Schools configure `RequiredDocument` rules (e.g., Birth Certificate, Passport, Medical Report).
4. **Campaign Engine:** Campaigns control application open/close dates, maximum applicants, application fees, allowed classes, and portal visibility.
5. **Admission Number Generation:** Numbering is generated by a dedicated `AdmissionNumberService` based on school-configured patterns (e.g., `2027/001`, `PRI-00054`).
6. **Multi-Review Engine:** Supports multiple reviewers scoring and commenting on an application before a final decision.
7. **Event-Driven:** Emits pure domain events (`ApplicationSubmitted`, `ApplicationReviewed`, `ApplicationEnrolled`) rather than synchronously triggering emails.
8. **Built-in Analytics & Reports:** Native tracking of Acceptance Rate, Enrollment Conversion, Rejection Rate, Average Processing Time, and standard reports (Daily Applications, Admission Statistics).
9. **Widgets:** Native dashboard widgets for New Applications, Pending Reviews, and Acceptance Funnels.
10. **Strict Audit Trail:** Every single action (Application Edited, Reviewer Changed, Document Uploaded) must be audited natively.

## Integration Points
- **Identity & Workspace:** Uses WorkspaceContext to identify the school, session, and applicant.
- **Finance Module:** Triggers an invoice generation when an application is submitted.
- **Communication Module:** Event subscribers dispatch emails/SMS based on Workflow status changes.
